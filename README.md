# Evaluating brand retrieval and ranking in open-ended LLM recommendations

This repository contains the data and code for the paper's category-only and needs-based brand recommendation experiments. It covers five product categories and six LLMs. All model requests used fresh sessions, no conversation history, and no web search or other retrieval tools.

## Study design

### Category-only recommendations

Each model received one prompt for each of five categories in 40 independent repetitions. This produced 1,200 ranked recommendation lists:

`5 categories × 6 models × 40 repetitions = 1,200 lists`

The analysis reports brand recommendation prevalence at ranks 1, 3, and 5 and brand-level MRR@5. Raw responses, canonical brand matches, alias rules, and the analysis script are included.

### Needs-based recommendations

The needs-based evaluation covers eight positioning dimensions. Each dimension has two endpoints, and each endpoint has three prompts. Running the 48 prompts across six models and 40 repetitions produced 11,520 ranked lists:

`8 dimensions × 2 endpoints × 3 prompts × 6 models × 40 repetitions = 11,520 lists`

Three LLM raters (Gemini, ChatGPT, and Claude) scored brands on the original category attributes. The repository includes the averaged ratings, the 212-brand final evaluation set, the final composite dimensions, the factor-analysis and reliability reports, all recommendation lists, and the code that recomputes NDCG@5.

### Marketplace analysis

The paper relates category-only recommendation prominence to advertising expenditure, news coverage, Google Trends search interest, Wikipedia pageviews, Brandwatch discussion, and Kantar BrandZ salience. Source extracts and measure definitions are in `data/marketplace/`.

Figure 1 uses the category-only recommendation workbook and the 210-brand marketplace file supplied with its R Markdown source. Its plot script recomputes BRP@5 from the 1,200 recommendation lists.

## Reproduce the recommendation analyses

Node.js 20 or newer is required.

```bash
npm install
npm run analyze
npm run verify
npm test
```

These commands recompute the category-only measures, independently verify all 11,520 stored NDCG@5 values, check the expected sample sizes, scan text files for identifying information and credentials, and run the brand-resolution tests.

The two paper figures require R with `dplyr`, `ggplot2`, `ggrepel`, `readr`, `readxl`, `stringr`, and `tidyr`:

```bash
Rscript analysis/plot-category-only-results.R
Rscript analysis/plot-positioning-results.R
```

The Figure 1 source notebook is in `analysis/figure1.Rmd`. To render it, also install `rmarkdown`, `psych`, and `glmnet`, then run `rmarkdown::render("analysis/figure1.Rmd")` from the repository root.

The 212-brand final set and positioning composites can be rebuilt from the averaged scores and the three recorded exclusions with:

```bash
Rscript analysis/construct-positioning-dimensions.R
```

## Repository map

| Path | Contents |
| --- | --- |
| `config/` | Model list, exact prompts, endpoint mappings, alias rules, and protocol settings |
| `data/raw/category-only/` | Archived responses for the 1,200 category-only tasks |
| `data/raw/positioning/` | Archived responses for the 11,520 needs-based tasks |
| `data/processed/` | Canonical recommendations, competitive-set review, positioning measures, reliability summary, and NDCG values |
| `data/marketplace/` | Available marketplace source extracts and measure metadata |
| `data/derived/` | Outputs regenerated by the analysis scripts |
| `analysis/` | Metric recomputation, figure generation, optional experiment runners, and integrity checks |
| `docs/` | Protocol, data dictionary, factor-analysis report, and reliability report |
| `provenance/` | Manifest for the archived source files |
| `CHECKSUMS.sha256` | SHA-256 checksums for the versioned artifact |

See [`docs/protocol.md`](docs/protocol.md) for the implemented protocol and [`docs/data_dictionary.md`](docs/data_dictionary.md) for file-level details.

## Optional live reruns

The archived results require no API credentials. New calls are optional. Copy `.env.example` to a local `.env`, add provider keys, and use the scripts under `analysis/`. New responses are written to the ignored `data/runs/` directory and do not overwrite the archived study files.

Some marketplace measures come from licensed commercial sources. Check the applicable redistribution terms before making a public release.
